# SRG-ARTIFACT-EVAL-01｜场景、检查器与证据

## 执行流程

场景构造真实初始状态和故障注入 → 被测路径执行 → 可信研究收集器保存可观察证据 → 独立检查器计算性质 → 外部比较器核对预期。检查器模块不导入 scenarios、Fault 或 ScenarioTruth。

## 结果不可混淆

`SATISFIED`、`VIOLATED`、`UNADJUDICABLE`、`EVIDENCE_CONFLICT`、`N/A` 是性质结果。`expectation_matched` 是测试是否正确重现其预期的结果。S15 应当是 G6=VIOLATED 且测试预期匹配，不得显示成“系统安全 PASS”。

B0 以凭证作治理根；B1 拥有稳定主体但保存/新鲜度不足；B3 为参考配置；B2 是同配置标签一致性控制，不是独立竞争基线。20 个定向场景不是流量样本，不生成概率性“安全率”。

## 观察与缺失

无实际效果：O1/O2 和逐效果 G4/G6 显示 N/A；O3 对生效限制的新请求仍适用，可以根据封闭观察区间得到 Satisfied。没有效果封口时不得对无限未来声称安全。

临时不可达：可以 Unknown。只有保存义务内、必要关系无独立恢复证据、所有契约恢复路径确认不可恢复时，才能 ConfirmedRbh。单条记录缺失、可选字段缺失、保留期结束或单个备份故障都不充分。

G3 在实际选用的快照内检查授权；G5 另检该快照的适用性。O2 从多个证据关系组合，而不是只验证授权 ID 存在。真实策略冲突与无法相容的事实声明分开。

## 组合与形式证据

P1/P2 由有限世界碰撞搜索提供见证，增强观察只证明消除了当前枚举世界中的冲突。P3 使用旧缓存且身份正确的轨迹。P4(a) 记录每个参考效果的实际前提和 O1/O2；P4(b) 运行正常资源端的生效撤销拒绝路径并检查 O3。组合结果仅为声明有限实例中的支持。

形式模型用单独的 TLA+ 和 Rust BFS 表达。配置删除后是否违反其他 G 不由故障标签决定；报告真实出现的全部性质违反，不假称独立最小性证明。

## 交付门槛

必须能够构建并执行20场景、重演 P1/P2、复现 P3、运行两个 P4 子组合、区分4种问责判定、检出两种 G4 故障和两种 G6 故障，并从原始文件机械生成表格。所有实际状态写入运行报告。未运行的 SoulAuth live 或 TLC 明确保留 NOT_RUN，不以设计文档中的 PASS 代替。
