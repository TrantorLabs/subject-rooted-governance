# Subject-Rooted Governance

**An executable research artifact for governing long-lived AI actors as persistent subjects.**

This repository is the companion artifact of the paper *Persistent Subjecthood and Responsibility Black Holes: A Subject-Rooted Governance Architecture for Long-Lived AI Actors* (TRANTOR LABS, 2026). The paper asks what has to stay attached to *the same actor* — roles, authority, restrictions, history — while everything around that actor (credentials, sessions, clients, runtimes) legitimately changes, and what breaks when it does not. This artifact turns the paper's six structural conditions (G1–G6), three target properties (O1–O3), four propositions (P1–P4) and the responsibility-black-hole verdict into something that can be **run, deliberately broken, independently checked and reproduced**.

It is a research harness, not a product: no IAM, no policy language, no real payments, no claim about AI alignment.

## What the artifact answers

| Paper object | Where it lives | How it is exercised |
|---|---|---|
| G1 subject & role resolution · G2 event-time provenance · G3 scoped authority basis · G4 complete mediation · G5 governance freshness · G6 decision-to-effect binding | `crates/srg-harness/src/checker.rs` — one independent checker per condition | 20 scenarios, each breaking one real structure (never a `g1 = false` switch) |
| O1 attribution closure · O2 authority correspondence · O3 post-revocation safety | same file — three checkers that recompute from evidence | every scenario × 4 baselines |
| Responsibility black hole (Closed / Unadjudicable / Confirmed-RBH / EvidenceConflict) | `AccountabilityChecker` | S16–S19, plus unit tests for the boundaries between the four |
| P1 online distinguishability · P2 historical reconstructability | `crates/srg-explorer` — finite-world collision search | weak observation collides, strengthened observation does not |
| P3 referential integrity ⇏ enforcement effectiveness | S12 (stale revocation) + explorer `StaleState` | G1 satisfied while O3 is violated |
| P4 bounded composition | `crates/srg-harness/src/composition.rs` | P4(a) retrospective closure on six reference effects; P4(b) prospective revocation safety |
| Formal core and two-world observability models | `formal/*.tla` | SANY + TLC executed; per-fault counterexample matrix cross-checked against the Rust search |
| SoulAuth authentication fact (upstream identity) | `crates/srg-soulauth` | contract-level adapter pinned to SoulAuth v0.3.0; **no live service is run** |

The four-valued verdict follows the paper's §3.8 exactly: **Satisfied** (every execution compatible with the evidence satisfies the property), **Violated** (every one violates it), **Unadjudicable** (compatible executions disagree), **EvidenceConflict** (no execution is compatible with the trusted evidence). A fifth label, **N/A**, marks a property with no applicable object — it is never counted as a pass.

## Quick start

Rust 1.82 or later. No database, no network, no external identity service.

```bash
cargo test --workspace --locked                 # 39 tests: core, checkers, scenarios, explorer, adapter
cargo run --locked -p srg-harness -- run-all    # 20 scenarios × 4 baselines → results/raw, traces, evidence
cargo run --locked -p srg-explorer -- all       # P1/P2 collisions and the 9-mutation bounded search
cargo run --locked -p srg-harness -- tables     # paper tables from the raw files (never re-runs silently)
```

One command for everything, with each step's real exit code recorded in `results/validation/verification.json`:

```bash
bash scripts/reproduce.sh
TLA2TOOLS_JAR=/path/to/tla2tools.jar bash scripts/reproduce.sh   # additionally runs SANY/TLC
```

Single pieces:

```bash
cargo run --locked -p srg-harness -- run S12                     # one scenario, prints its reports
cargo run --locked -p srg-harness -- run S12 --baseline B0
cargo run --locked -p srg-harness -- suite rbh                   # the four accountability verdicts
cargo run --locked -p srg-harness -- suite p4                    # the bounded composition suites
cargo run --locked -p srg-harness -- audit results/raw/scenarios/B3/S12.json   # re-check an archived run
cargo run --locked -p srg-explorer -- p1                         # or p2 / core
```

`--out DIR` redirects the output tree.

Some rows are worth reading twice:

- **S06 and S18 are different failures.** Committing provenance after the commitment boundary breaks G2, but the history is still recoverable, so accountability closes. Permanently losing the only event-time relation, with every contract recovery path confirmed lost, is the black hole. A G2 breach is not automatically an RBH.
- **S11 breaks G4 and O3 while accountability stays Closed.** The resource executed after an explicit Deny; the system nevertheless recorded exactly who did it. Enforcement failed, attribution did not — the paper's point that the two are independent.
- **S12 is the P3 witness.** Subject and revocation are correctly attributed (G1 satisfied), the gateway used a stale snapshot (G5 violated) and the effect happened (O3 violated).
- **S15 violates G6 with identical action content**: one single-use admission, two independent ledger effects. Content binding alone would have passed it.
- **S16 closes through a correction**: the first provenance record named the wrong subject, a later record corrects it and points back at the original, and the original is retained. Delete the original and the same correction becomes indistinguishable from a silent overwrite — the checker then returns Unadjudicable (`correction_closes_only_when_the_original_is_retained`).
- **A negative scenario detecting its fault is a test pass and a property violation at the same time.** `expectation_matched` and the verdict are never merged into one PASS.

Baselines: **B0** roots the subject in the credential (G1 fails on every scenario, and a legitimate multi-role action is falsely denied), **B1** has a stable subject but no provenance commitment and stale governance state, **B3** is the full reference configuration, **B2** is B3 under a different label — a checker-consistency control, not a competitor. `results/tables/baseline_matrix.csv` has all 80 rows.

Bounded search (`results/raw/explorer/core.json`): the unmutated model reaches 9 states with no counterexample; each of the 8 mutations reaches 9–11 states and violates the properties listed in `results/formal/tlc_matrix.json` — TLC and the Rust search agree cell for cell (`tlc_matrix_agrees_with_bfs`). P1 has 16 weak-observation collisions and 0 once the trusted subject is observed; P2 has 8 and 0 once the event-time binding is observed.

## Reading the evidence

```text
results/
├── raw/scenarios/<baseline>/<id>.json   evidence + trace + reports + expected outcome + ground truth
├── evidence/<baseline>/<id>.json        the EvidenceSet alone — what the checkers were given
├── traces/<baseline>/<id>.json          the event chain behind every verdict
├── raw/explorer/{core,p1,p2}.json       bounded search and collision witnesses
├── raw/p4/                              composition instances and report
├── tables/                              scenario_matrix, baseline_matrix, g_ablation_matrix, rbh_matrix, p4_matrix
├── formal/{status,tlc_matrix}.json      the last SANY/TLC execution
├── manifests/run_manifest.json          source fingerprint, Cargo.lock hash, toolchain, contract and registry ids
└── summary.json
```

The checkers receive `EvidenceSet + ResearchContract + QueryContext` and nothing else. The scenario id, the injected fault, the expected outcome and the ground truth live in the same raw file for auditability, but `verdict_does_not_read_expected_or_truth` rewrites all of them and asserts the reports do not change, and `srg-harness -- audit` re-derives the archived reports from the evidence alone.

Sources are a trust contract, not authentication: an envelope whose `source` is not the contract's declared source for that channel is ignored (`unknown_source_cannot_claim_trust`). Absence is not proof of absence: a checker only concludes "no such admission" or "no such effect" when an `ObservationSeal` from the declared collector covers that channel through the query point.

## Formal models

`formal/P2_Core.tla` is the single-chain governance core (two subjects, one request, at most two effects, eight fault mutations); `formal/P2_Observability.tla` is the two-world model behind P1/P2. Both are executed by `scripts/check-formal.sh` with the official tools — SANY for both, TLC on the reference configuration (all invariants hold, 9 states), on the observability model (both witnesses exist, both strengthened observations resolve) and on every `(fault, property)` pair, which is what produces `results/formal/tlc_matrix.json`. CI downloads a pinned `tla2tools.jar` (v1.8.0, SHA-256 verified), re-runs everything and fails if the committed matrix differs.

The Rust explorer is a deterministic BFS over the same state space, not a replacement for TLA+; `docs/FORMAL_RUST_MAPPING.md` maps variables, actions and properties one to one. A TLC pass over this model is bounded evidence, not a general proof.

## What is and is not claimed

Claimed, and checkable from this repository:

- G1–G6 each have an executable structure and at least one independent fault witness; G4 covers both bypass and deny-then-effect; G6 covers both content substitution and admission replay.
- O1–O3 are recomputed by checkers that never read the fault, the expectation or the ground truth.
- The four accountability verdicts are each reproduced by a distinct scenario, and the boundaries between them (retention expiry, temporary unavailability, alternative recovery path, missing correction target) are unit-tested.
- P1–P3 counterexamples are machine-reproducible; P4(a) and P4(b) have bounded executable support in the declared reference contract.
- The core evidence is deterministic: same commit, same `Cargo.lock`, same bytes (CI diffs the committed results against a fresh run).

Not claimed:

- A general proof of P4, or of the necessity or sufficiency of G1–G6 beyond the declared bounded models.
- Any production, concurrency or partition-tolerance validation; any real funds.
- A live SoulAuth integration. `srg-soulauth` adapts the `AuthenticationFact` shape of SoulAuth v0.3.0 (commit `0830d1733b911558484006d61c463e8b90e9eab5`) behind an `AuthenticatedFactTransport` trait that the integrator must implement over an authenticated channel; parsing JSON is not authentication. Every run manifest says `identity_provider: deterministic`, `soulauth_live: NOT_RUN`.
- Anything about AI consciousness, intent or legal liability.

The scenarios are directed witnesses, not a traffic sample; no number in `results/` is a probability of safety.

## Repository layout

```text
crates/srg-core        types, reference contract, evidence envelopes, four-valued reduction — no I/O
crates/srg-harness     controlled ledger (SUT), 10 checkers, 20 scenarios × 4 baselines, tables, composition
crates/srg-explorer    finite worlds, observation collisions, bounded BFS with 8 mutations
crates/srg-soulauth    SoulAuth v0.3.0 authentication-fact adapter behind a transport trait
formal/                P2_Core.tla, P2_Observability.tla, per-fault TLC configurations
scripts/               reproduce.sh, check-formal.sh
docs/                  the three frozen design baselines (CONF-01, CORE-01, EVAL-01), formal↔Rust mapping,
                       reproducibility notes, and ARTIFACT_DELTA.md — every place the artifact and the
                       paper text still differ, classified
results/               the committed evidence described above
```

The design baselines in `docs/` call this generation of the artifact "v1.0"; the software release is **0.1.0**, the first public one. What 0.1.0 satisfies is the baselines' release gates.

## Reproducibility and citation

Pin the tag, the commit and the archive checksum together; `main` moves. The run manifest records the source fingerprint (every tracked file except `results/`), the `Cargo.lock` hash and the toolchain, so a result file can be tied to the exact source that produced it.

```text
Subject-Rooted Governance v0.1.0, TRANTOR LABS, 2026.
https://github.com/TrantorLabs/subject-rooted-governance
```

[CITATION.cff](CITATION.cff) carries the same metadata for GitHub's *Cite this repository*. The DOI is added once the release archive is deposited.
